El loop encadena

Cada herramienta vuelve al modelo como role:"tool" y el loop sigue. Tres o cuatro llamadas en un turno, no una.

La política manda, no el modelo

El servidor resuelve getSupliaPolicy(nombre) sobre la herramienta que llegó. El modelo pide; nunca decide su propio permiso.

El costo se ve antes

Toda acción con credits > 0 muestra créditos y alcance en la tarjeta. El violeta está reservado para eso.

Aprobar continúa el turno

El resultado vuelve al loop y el modelo lo analiza. Nunca una plantilla fija como successMessage().

El turno vive en la base

suplia_turn_events es append-only. Cerrar el navegador no pierde el turno: se reanuda por seq.

El artefacto es el entregable

Listas, reportes y borradores salen del hilo al canvas, versionados y exportables a xlsx, csv o pdf.

Datos de ejemplo: empresas, contactos y cifras son ficticios, para mostrar el comportamiento de la interfaz. Los nombres de herramientas, tiers de modelo y estados corresponden al catálogo real de src/lib/server/suplia-tools.ts.
